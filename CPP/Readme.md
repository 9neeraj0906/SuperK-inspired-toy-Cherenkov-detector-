# Custom C++ Neutrino Physics

This directory contains the custom C++ components developed to add a simplified neutrino interaction to the Geant4-Python simulation.

The C++ code was written because the required custom neutrino interaction was not implemented directly in the Python layer used by this project. The C++ classes are exposed to Python through `pybind11` and are then used from `Physics.py`.

---

## Files

### `NeutrinoCCQEProcess.hh`

Header file for the custom neutrino interaction process.

It declares the `NeutrinoCCQEProcess` class, which inherits from:

```cpp
G4VDiscreteProcess
```

The process implements the Geant4 methods required for a discrete interaction:

- `IsApplicable()`
- `GetMeanFreePath()`
- `PostStepGetPhysicalInteractionLength()`
- `PostStepDoIt()`

### `NeutrinoCCQEProcess.cc`

Implementation of the custom neutrino interaction.

The process is currently applicable to muon neutrinos (`nu_mu`).

When the process occurs, it creates:

```
nu_mu -> mu- + proton
```

The current implementation creates the secondary particles with fixed kinetic energies:

| Particle | Kinetic energy |
|----------|----------------|
| `mu-`    | 400 MeV        |
| `proton` | 100 MeV        |

Both particles are initially given the neutrino's momentum direction. The incoming neutrino track is then stopped and removed.

#### Important limitation

This is **not** a physical CCQE interaction generator.

The current implementation does not calculate:

- Neutrino-nucleon cross sections
- Interaction probabilities
- Realistic CCQE kinematics
- Nuclear effects
- Fermi motion
- Binding energy
- Momentum-transfer distributions
- Realistic muon/proton angular distributions
- Energy-dependent interaction rates

The process is forced to occur and uses fixed secondary-particle energies. Therefore, it should be regarded as a toy interaction used to provide a neutrino-to-muon starting point for the detector simulation.

### `NeutrinoCCQEPhysics.hh`

Header file for the custom Geant4 physics constructor.

It defines `NeutrinoCCQEPhysics`, which inherits from:

```cpp
G4VPhysicsConstructor
```

This class provides the interface used by Geant4 to register the custom neutrino process.

### `NeutrinoCCQEPhysics.cc`

Implementation of the custom physics constructor.

The constructor obtains the Geant4 definition of the muon neutrino:

```cpp
G4NeutrinoMu::NeutrinoMuDefinition()
```

and accesses its `G4ProcessManager`.

The custom `NeutrinoCCQEProcess` is then registered as a discrete process for the muon neutrino. This allows the process to be used by the Geant4 tracking system when the simulation is run.

### `pyNeutrinoCCQEPhysics.cc`

This file provides the `pybind11` interface for the custom physics constructor.

It exposes `NeutrinoCCQEPhysics` to Python so that it can be registered from the Python physics list. This allows the Python simulation to use:

```python
NeutrinoCCQEPhysics()
```

without rewriting the actual Geant4 process in Python.

### `pyNeutrinoCCQEProcess.cc`

This file contains the `pybind11` interface associated with the custom neutrino process.

A direct Python registration function was also implemented during development:

```python
RegisterNeutrinoCCQE(...)
```

However, the direct registration route was not used in the final simulation because it caused segmentation faults in the Python binding environment.

The final working implementation uses:

```
NeutrinoCCQEPhysics
        |
        v
NeutrinoCCQEProcess
```

and registers the process through the Geant4 physics-constructor mechanism.

## How the C++ Physics Is Used

The custom physics is registered from the Python physics list. The relevant structure is:

```
Python
  |
  v
NeutrinoCCQEPhysics()
  |
  v
G4ProcessManager
  |
  v
NeutrinoCCQEProcess
  |
  v
nu_mu interaction
  |
  +----> mu-
  |
  +----> proton
```

The resulting muon is then propagated through the water detector by the normal Geant4 tracking and physics processes.

The Cherenkov photons are **not** generated by this custom C++ code. They are produced by Geant4's optical physics after the muon propagates through the water.

---

## Relationship to the Detector Simulation

The custom C++ interaction is only the first part of the simulated event:

```
nu_mu
  |
  | Custom toy CCQE process
  v
mu- + proton
  |
  | Standard Geant4 tracking
  v
muon propagation through water
  |
  | G4OpticalPhysics
  v
Cherenkov photons
  |
  v
PMT detection
```

Thus, the C++ code is responsible for providing the simplified neutrino interaction, while the subsequent particle propagation and optical simulation are handled by Geant4.

---

## Accuracy and Scope

This implementation should not be interpreted as a realistic neutrino event generator or a precision neutrino-interaction model. The custom interaction is intentionally simplified.

In particular:

- The interaction probability is forced rather than calculated from a physical cross section.
- The muon energy is fixed at 400 MeV.
- The proton energy is fixed at 100 MeV.
- The secondary directions are initially identical to the neutrino direction.
- No nuclear model is implemented.
- No realistic target-nucleus kinematics are implemented.
- No neutrino energy spectrum is generated by this C++ process.
- No oscillation physics is implemented in this process.
- No detector calibration or experimental response is included here.

The purpose of this implementation is therefore not to reproduce the Super-Kamiokande neutrino interaction rate or event kinematics. Instead, it provides a controlled neutrino-interaction starting point for studying the downstream detector simulation:

```
neutrino interaction
        ->
muon propagation
        ->
Cherenkov production
        ->
PMT detection
        ->
direction reconstruction
```

---

## Validation of the Downstream Simulation

Although the neutrino interaction itself is a toy model, the subsequent optical simulation was separately checked.

The Geant4 Cherenkov process was used to generate optical photons, and the simulated local Cherenkov angle was found to be approximately **40.09°**, compared with a theoretical value of approximately **40.06°**.

The photon creation-to-PMT tracking association was also validated using Geant4 track IDs.

These checks validate parts of the optical detector simulation, but they do not make the custom CCQE interaction physically accurate.

---

## Summary

The C++ implementation provides a minimal custom neutrino interaction for the Geant4-Python simulation. Its role is:

```
nu_mu
  |
  v
Toy CCQE interaction
  |
  +----> mu-
  |
  +----> proton
```

The muon is subsequently passed to the standard Geant4 tracking and optical physics used by the detector simulation.

The implementation is intentionally a toy model and should be treated as a framework for studying the detector and reconstruction chain rather than as a realistic model of neutrino-nucleus scattering. A realistic neutrino simulation would require a dedicated neutrino interaction generator and physically motivated cross sections and nuclear models.
